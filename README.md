# 台股風險燈號追蹤系統

用自己設的規則取代別人給的點位預測。

**起因：** 2026 年 10 月，分析師杜金龍以波浪理論推估台股 2027 年 5 月可能挑戰
53,000–60,000 點，並計畫在該時點前後把持股降到 5 成以下。這套系統不預測點位，
改用可觀察的風險指標與固定的減碼階梯來做同一件事。

## 通知規則

**每個交易日 16:47（台北）檢查一次。只有燈號有意義地變化時才通知。**

| 轉換 | 通知？ |
|---|---|
| 🟢 → 🔴 新增風險 | **是** |
| 🔴 → 🟢 風險解除 | **是** |
| ⚪ → 🔴 補資料後發現已達門檻 | **是** |
| ⚪ → 🟢 只是補上資料 | 否 |
| 🔴 / 🟢 → ⚪ 資料遺失 | 否 |

## 常用指令

```bash
python3 scripts/risk_check.py --show                  # 目前狀態
python3 scripts/risk_check.py --set pb=4.6 --dry-run  # 試算，不寫檔
python3 scripts/gen_indicator_doc.py                  # 改過 config 後重產說明文件

# 補上四個灰燈需要的數值（從看盤軟體讀，一次輸入會沿用）
python3 scripts/risk_check.py --set \
  bias_240=24.5 yield_gap=0.8 dividend_yield=2.3 bond_yield_10y=1.5 \
  down_days_20=12 vol20_vs_prev_peak=92
```

## 檔案結構

```

data/config.json              門檻、權重、查詢關鍵字 ← 唯一的設定來源

scripts/risk_check.py         燈號引擎
scripts/gen_indicator_doc.py  指標說明產生器
```

## 設計原則

1. **規則先寫，不事後解釋。** 門檻存在 `config.json`，改動會留在 git 歷史裡。
   想降低門檻讓自己好過，會被記錄下來。
2. **只有紅綠兩態。** 不設橙燈。中間狀態會變成拖延的藉口。
3. **分數優先於點位。** 體質壞掉時價格可能還在漲，但那段漲幅的風險報酬比很差。
4. **只在變化時通知。** 降低雜訊，保留訊號的注意力價值。
5. **推算的數字要標明。** 每個指標顯示資料日期，推算值在「資料備註」寫出方法。
